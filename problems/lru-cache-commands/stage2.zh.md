# LRU 缓存模拟器（第二阶段）

## 新需求

上线后，运维提出了两个需求：一是能主动删除某个键，二是能在运行时调整缓存容量。同时线上流量大了很多，你的实现需要能高效处理大量命令。

第一阶段的所有规则（`GET`、`PUT` 的行为与输出）保持不变。新增两种命令：

- `DEL k`：如果键 `k` 在缓存中，把它删除并输出 `1`；否则输出 `0`。删除操作不影响其他键的使用顺序。
- `RESIZE c`：把缓存容量改为 `c`。如果当前缓存中的键数超过 `c`，就按 LRU 顺序反复淘汰最久未使用的键，直到键数不超过 `c`。输出这次淘汰的键数（可能为 `0`）。`RESIZE` 不改变剩余键的使用顺序。

之后的 `PUT` 按新容量判断是否需要淘汰。

## 输入格式

第一行两个整数 `C Q`。

接下来 `Q` 行，每行一条命令：`GET k`、`PUT k v`、`DEL k` 或 `RESIZE c`。

## 输出格式

对每条 `GET`、`DEL`、`RESIZE` 命令，按顺序输出一行结果。`PUT` 不产生输出。

## 数据范围

- `1 ≤ C ≤ 2 × 10^5`，`RESIZE` 中 `1 ≤ c ≤ 2 × 10^5`
- `1 ≤ Q ≤ 2 × 10^5`
- `0 ≤ k ≤ 10^9`
- `0 ≤ v ≤ 10^9`

请确保每条命令的均摊时间复杂度足够低。

## 样例 1

输入：

```
3 10
PUT 1 1
PUT 2 2
PUT 3 3
DEL 2
DEL 2
PUT 4 4
GET 1
RESIZE 1
GET 4
GET 1
```

输出：

```
1
0
1
2
-1
1
```

解释：

- 第一次 `DEL 2` 删除成功，输出 1；第二次时 2 已经不在缓存中，输出 0。
- 删除后缓存里只有 2 个键，所以 `PUT 4 4` 不需要淘汰。
- `GET 1` 输出 1。此时从最久到最近的顺序是 3、4、1。
- `RESIZE 1` 需要淘汰到只剩 1 个键：依次淘汰 3 和 4，输出 2。
- `GET 4` 输出 -1，`GET 1` 输出 1。

## 样例 2

输入：

```
2 8
PUT 1 100
RESIZE 3
PUT 2 200
PUT 3 300
PUT 4 400
GET 1
RESIZE 2
GET 3
```

输出：

```
0
-1
1
300
```

解释：

- `RESIZE 3` 扩容，不需要淘汰，输出 0。
- 放入 2、3 后共 3 个键，缓存已满。`PUT 4 400` 淘汰最久未使用的 1，所以 `GET 1` 输出 -1。
- `RESIZE 2` 时有 3 个键（2、3、4），淘汰 2，输出 1。
- `GET 3` 输出 300。
