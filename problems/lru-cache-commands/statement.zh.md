# LRU 缓存模拟器（第一阶段）

## 背景

你在为一个服务实现内存缓存。缓存容量有限，满了以后需要淘汰数据。我们采用 **LRU（Least Recently Used，最近最少使用）** 策略：需要淘汰时，移除**最久没有被访问过**的那个键。

## 规则

缓存初始为空，容量为 `C`。依次处理 `Q` 条命令：

- `GET k`：如果键 `k` 在缓存中，输出它对应的值，并把 `k` 标记为"最近使用"；否则输出 `-1`。
- `PUT k v`：
  - 如果键 `k` 已在缓存中，把它的值更新为 `v`，并标记为"最近使用"。这种情况**不会**发生淘汰。
  - 否则，如果缓存中已有 `C` 个键，先淘汰最久未被使用的那个键；然后插入 `(k, v)`，并标记为"最近使用"。
  - `PUT` 命令**不产生输出**。

"使用"指成功的 `GET` 和任何 `PUT`。未命中的 `GET` 不改变任何状态。

## 输入格式

第一行两个整数 `C Q`，分别表示缓存容量和命令条数。

接下来 `Q` 行，每行一条命令，格式为 `GET k` 或 `PUT k v`。

## 输出格式

对每条 `GET` 命令，按顺序输出一行结果。

## 数据范围

- `1 ≤ C ≤ 100`
- `1 ≤ Q ≤ 1000`
- `0 ≤ k ≤ 10^9`
- `0 ≤ v ≤ 10^9`

## 样例 1

输入：

```
2 9
PUT 1 10
PUT 2 20
GET 1
PUT 3 30
GET 2
PUT 4 40
GET 1
GET 3
GET 4
```

输出：

```
10
-1
-1
30
40
```

解释：

- 放入 1、2 后缓存已满。`GET 1` 输出 10，此时 1 成为最近使用，2 成为最久未使用。
- `PUT 3 30` 时缓存已满，淘汰 2。所以 `GET 2` 输出 -1。
- 此时缓存中有 1 和 3，1 更久未被使用。`PUT 4 40` 淘汰 1。
- 最后 `GET 1` 输出 -1，`GET 3` 输出 30，`GET 4` 输出 40。

## 样例 2

输入：

```
2 7
PUT 5 1
PUT 6 2
PUT 5 3
PUT 7 4
GET 6
GET 5
GET 7
```

输出：

```
-1
3
4
```

解释：`PUT 5 3` 更新已有的键 5，不淘汰任何键，并把 5 标记为最近使用。所以 `PUT 7 4` 淘汰的是 6 而不是 5。
