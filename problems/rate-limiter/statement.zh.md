# 按用户的滑动窗口限流器

一个 API 网关需要对每个用户单独限流：任意一个长度为 `W` 秒的时间窗口内，同一个用户最多有 `K` 个请求被放行。

具体规则：一个在时刻 `t` 到达的请求，如果该用户在区间 `(t - W, t]` 内**已被放行**的请求数小于 `K`，就放行，否则拒绝。被拒绝的请求不计入之后的统计。

## 输入

第一行三个整数 `W K Q`。

接下来 `Q` 行，每行一条命令：

```
REQ t user
```

表示用户 `user` 在时刻 `t` 发来一个请求。`t` 按输入顺序单调不减。`user` 是不含空格的字符串。

## 输出

对每条 `REQ` 输出一行：放行输出 `ALLOW`，拒绝输出 `DENY`。

## 数据范围

- `1 ≤ W ≤ 10^9`，`1 ≤ K ≤ 10^5`，`1 ≤ Q ≤ 2×10^5`
- `0 ≤ t ≤ 10^9`

## 样例 1

输入

```
10 2 5
REQ 1 alice
REQ 2 alice
REQ 3 alice
REQ 3 bob
REQ 11 alice
```

输出

```
ALLOW
ALLOW
DENY
ALLOW
ALLOW
```

解释：alice 在时刻 3 的请求到来时，窗口 `(-7, 3]` 内已有 2 个放行的请求，所以拒绝。时刻 11 时窗口是 `(1, 11]`，时刻 1 的请求已经滑出，窗口内只剩时刻 2 的那一个，所以放行。

## 样例 2

输入

```
5 1 5
REQ 0 a
REQ 0 a
REQ 0 b
REQ 5 a
REQ 5 a
```

输出

```
ALLOW
DENY
ALLOW
ALLOW
DENY
```

解释：同一时刻的多个请求按输入顺序处理。a 在时刻 0 的第二个请求到来时，窗口内已有 1 个放行的请求，所以拒绝；b 单独计数，放行。时刻 5 时窗口是 `(0, 5]`，时刻 0 的请求已经滑出，所以 a 的第一个请求放行，第二个拒绝。
